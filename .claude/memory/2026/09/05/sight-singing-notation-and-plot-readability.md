## 2026-09-05 — 视唱能用了：让测试唱歌，把画布变成页面的一部分

承接 [ear-training-scope-and-core-layering](../04/ear-training-scope-and-core-layering.md)（六步实施 + 首轮审计，到 v2.6.0）。
本条覆盖其后的四个提交 `548e60c → f088edd`，版本 **2.6.0 → 2.9.0**。
起点是用户两句话：**"视唱明显不可用！你需要端到端调试！"** 和 **"视唱你要给五线谱或简谱啊！你给这个有什么用？"**

### 让测试唱歌 —— 一次挖出三个真 bug
浏览器的 `--use-file-for-fake-audio-capture` 只能播一个固定文件，**它没法唱屏幕上那条谱**。
改用 `addInitScript` 在页面主世界里装一个**合成歌手**：振荡器 → `MediaStreamDestination` → 覆盖 `getUserMedia`；
测试从 DOM 读出写好的旋律（`data-sing-plan`），**在页面内等预备拍**（往返延迟会把第一个音抹掉半拍），
再按拍把每个音唱出来。断言是"唱准的一遍必须得分"。三个 bug 只有这样才会露头：

1. **检测频带被上一个乐器锁死**。`activateTuner()` / `deactivateTuner()` 存在、导出、写得也对 —— **没有任何视图调用过**。
   于是选过吉他（E2–E4）之后去视唱，高音一律测不到，整段判"漏唱"。视唱现在自己设人声频带并在退出时清掉。
2. **判分读的是显示用的平滑音高**。`PitchSmoother` 对最近 **360 ms** 做加权平均（指针要稳），
   而 833 ms 的音里前 40% 还带着上一个音的频率 —— 唱得准，判出来是一串"差一点"。
   快照现在同时带 `rawPitch`：**指针读平滑值，时间序列和判分读原始值**。history 与 judge 都改读后者。
3. **起音容差太小**。没人的起音落在毫秒上，25% 不够吃掉"晚一点点"，改成 34%（仍留 52% 供判分）。

结果：唱准的一遍 **8/8 全 good**，这条端到端断言进了 smoke。

### 画面空白 —— rAF 不能读 Vue computed 里的音频时钟
用户报"谱图啥也没有"。逐层排查（像素直方图 → 历史缓冲列数 → analyser 读数 → 连接图）后定位：
`TraceCanvas` 的时间窗是个 `computed`，而 **`AudioContext.currentTime` 不是响应式的** ——
它只在首次渲染求值一次（那时 context 还是 null，`?? 0`），于是画面永远停在 `[-10s, 0]` 这个早已过去的窗口。
修法：窗口改成**每帧调用的函数**（`range?: (now) => {start,end}`）。
这个 bug 单测和类型都抓不到，**只有像素能**：smoke 现在对合成麦克风发声并断言画面亮起来（147 个亮采样）。

排查中还两次被**测试自身的伪影**误导，值得记下：
- 我的自动化标签页是 `visibilityState: hidden` → rAF 被暂停 → 画布停在 300×150 默认尺寸；
- 探针没带 `--autoplay-policy=no-user-gesture-required` → 合成 context 挂起 → 两个 analyser 都读 −Infinity；
- app 停止时会 `track.stop()`，把合成流**永久**停掉 → 假麦克风必须每次返回新的 destination stream。

### 浅色模式很丑 —— 画布有一套与页面无关的视觉体系
两个根因，都是"画布自己发明规则"：
- **不画底色**。于是暗底色阶（magma 从近黑起步）在白页面上就是一个黑洞。
  现在画布用 `--plot-surface` 画自己的底；色阶分 **onDark / onLight 两族**（新增纸墨 paper、墨色 ink），
  `defaultColormap(polarity)` + `colormap: "auto"` 跟随主题 —— 用户仍可显式指定。
- **刻度密度只看音域、不看像素**。`tickBudget(pixels)` 给出标签预算，
  自动降级：变化音 → 音名 → 整八度（且对齐到 C，剩下的读起来仍是音阶而不是随机采样）。
时间轴同理按宽度选步长。空状态也不再横压在坐标轴上（那看起来像渲染坏了），改成空白区里的一张卡。

### 五个组件在回答同一个问题
按钮行 + 设备下拉 + 设备标签 + 状态药丸 + 隐私说明 + 独立电平表 —— 都在回答"app 在不在听、听什么"。
合成一个 `AudioSource`：**按钮说明下一步动作**，电平直接填充按钮本体，设备选择只在有多个设备时出现。
会话是应用级的，所以**麦克风全程只启动一次**；`retention.ts` 用引用计数 + 微任务延迟检查，
让会话跨工具存活、又在没有工具需要时释放（路由切换先卸载旧视图再挂载新视图，不延迟就会把每次导航看成"最后一个持有者离开"）。
视唱与声图重复的画布抽成 `shared/components/TracePlot.vue`：声图加热力图与拖动回看，视唱加写谱线。

### 视唱：围绕回路重设计 + 真的给谱
- **一个循环、一个按钮**。五个按钮（给主音/听旋律/开始唱/连续练习/换一条）塌缩成 `开始 / 停止`；
  主音、预备拍、判分、换下一条全在循环内自动发生。**主按钮永不禁用** —— 没麦克风就自己去取
  （"禁用主按钮直到用户自己找到别的控件"正是"不可用"的来源）。试听/换一条降级为动作，摆在启停旁。
- **记谱**（用户："你给这个有什么用？"）：音高曲线是**结果**，不是要读的东西。
  `lib/notation.ts` 是纯布局 —— 谱表步（字母而非半音）、五度圈调号、加线、符干方向、简谱级数与八度点；
  组件只把"步"变成 SVG，**不引音乐字体、无资源**。谱面同时是反馈面：唱时光标沿谱走，判分后每个音染上自己的颜色。
- **音域移位**（男声）：`原调 / 低八度`。男中音把女高音的谱低八度唱是**对的**，
  所以发声、画线、判分三处都跟着音域走，**写下来的谱不动**（标 `8vb`）—— 这才是"音域"的含义。
  判分因此从"八个八度误差"变成"唱对了"。
- **app 不录自己的声音**：参考音、预备拍、试听都从扬声器出去又被麦克风收回来，会画进 take 甚至进判分。
  `holdHistory(seconds)` 在 app 自己发声期间暂停采集。
- 控件按**它回答的问题**分组（读谱 / 音域 / 调 / 速度 / 小节），记谱改成**分段选择**（两个选项都在、当前项高亮）。

### Reusable insight
- **点在"往返"上的功能，必须从往返测**，而且**测试要能表演**：浏览器的假采集设备唱不出屏幕上的谱，
  三个真 bug 恰好住在别的手段都看不到的地方。把振荡器接成 `MediaStream` 覆盖 `getUserMedia`，测试就成了演奏者。
- **一个数不能同时服务两个主人**：指针要平滑，时间序列和判分要原始。
  发现"显示优化"污染了判定，就该在快照里并列两条，而不是调平滑参数。
- **rAF 循环里要读的时钟，就在循环里读**。`currentTime` 不是响应式的，`computed` 会把它冻在第一次求值上。
- **标签等于自身当前状态的控件是歧义的**（"五线谱"是"你在读"还是"点我切"？）—— 选择用分段控件，开关才用单键。
- **主动作永不禁用**：它应该去获取自己需要的东西。禁用 + 一行提示 = 用户眼里的"不可用"。
- **app 不该录自己的输出**。凡是"从扬声器出去又能被麦克风听见"的声音，采集期间都要挂起。
- **调试要先怀疑观测装置**：隐藏标签页会暂停 rAF、缺 autoplay flag 会让合成 context 挂起、
  `track.stop()` 会永久废掉复用的假流 —— 三次伪影都伪装成"应用坏了"。
