## 2026-09-13 — 让乐器成为会共振的东西,而不是波形

### 起点:"音色现在不对啊,电子感太强了"
用户要求逐个检查,并要三档可选:**纯合成 / 混合(合成+关键采样) / 真实采样**。

### 根因不是波形,是衰减
**振荡器给每个泛音同样的衰减;真实的弦给高次泛音短得多的寿命。**
耳朵把这个差别读成"有东西在共振"而不是"有东西在放波形",换什么波形都买不回来。

### 为什么必须离线渲染(一个硬约束)
**Web Audio 做不了 Karplus-Strong**:`DelayNode` 反馈环的最小延迟是一个 128 样本
渲染块,48000Hz 下**上限约 375Hz**——再高模型就不再是弦。所以模型在 `lib/` 里
用纯算术渲染成 `Float32Array`。这带来第二个好处:**模型的物理性质变成 Node 能断言的
东西**,而不是只能"相信浏览器"。

### 四个模型,每个都有一条只有测试能发现的教训

**弦(`renderString`)** — 延迟线 + 阻尼低通 + 全通链(刚度) + 拨弦位置梳状 + 琴体共振峰。
- **环路滤波器自身的相位延迟是周期的一部分**。漏掉它就跑调,且阻尼越重越跑——
  这是 Karplus-Strong 的经典错误。补上后四个八度内误差 < 8 音分。
- **一阶全通两节几乎不产生弥散**:c=0.4 的两节在六次泛音上只差 0.02 个采样,
  而一个来回是 200 个。需要**四节 + 更大的系数**才能让"拉伸"真的是拉伸。
- 琴体共振峰**不随音高移动**——这是"吉他"和"装了不同滤波器的同一条弦"的区别。
  测试断言同一个 500Hz 共振峰在 250Hz 和 200Hz 两个音上都被抬起。

**模态(`renderModal`)** — 敲击棒/音叉/卡林巴。棒是**非谐**的(1 : 6.27 : 17.5),
弦是 1:2:3;这就是八音盒不是钢琴的原因。

**鼓(`renderDrum`)** — 降调模态 + 噪声带。**皮膜被压得越深越硬**,所以音头偏高再落回;
把音高按住它就不再是鼓,而是低音"哔"。军鼓要**两条噪声带**(鼓皮一条、响弦一条),
一条带不可能同时是两者。

**管(`renderWind`)** — 这个是三个失败版本换来的:
1. **把非线性放在环路之外会啸叫**。单独的加性高增益驱动项让环路的谐振结构不再重要,
   哪个高次模赢就是哪个。弓弦之所以能锁频,是因为**饱和作用在环路自身的信号上**。
2. **管子的损耗随频率增长**(辐射 + 黏热),这才是从所有模式里挑出基频的东西。
   没有它,管子会在 10kHz 上叫。
3. **射流是气流不是嘶嘶声**。真实的射流是被管子锁相的连续气流;把等量的白噪声灌进去
   就只是噪声——而且**测出来也像噪声**。

### 两条"放大器"级的教训

**摩擦会饱和,而饱和不能按峰值归一化。**
驱动式模型(弓/管)按峰值归一化会**让重弓比重弓更轻**——按得越重波形越"方",
峰均比越大,归一化后 RMS 反而更低。这个 bug 是测试当场抓到的:
`expected 0.2548 to be greater than 0.5095`。响度必须是模型的性质。

**呼吸噪声不能衰减,而且必须跟音高走。**
气息是持续的,不是瞬态——给它一条衰减包络会让嘶嘶声在一个还在响的音下面先死掉。
更要紧的是**它的位置**:中心落在基频上不是"音符上的空气",是"盖在音符上的枕头"。

### 最锋利的一条断言:**app 自己的音高检测器必须能听出它**
它抓到了别的方法抓不到的错误:breath 比音本身还响(占能量 43%)。
那听起来在频谱图上完全合理,但是**不可用**——而 YIN 的 CMND 最小值是 0.588
(干净音应该 < 0.1)把它指了出来。修完后 0.217,YIN 锁定,置信度 0.75。

### 26 件乐器全部可演奏
原本 18 件。缺的是**整个弓弦家族 + 古筝 + 古琴 + 卡林巴 + 口琴**——它们没有
`surface` 也没有 `timbre`,在调音器里而在演奏页里不存在。**没有任何东西失败,
它们只是不在那儿**,而玩家是"找不到小提琴"时才知道的。

新增三个演奏面,每个都拒绝借用别的乐器的形状:
- `stopped` — 手指按的弦。格子还是"从空弦往上几个半音",**缺的只是品本身**,
  所以是同一个棋盘,只是不画品记。
- `tines` — 卡林巴的音板。**这个顺序就是乐器**:最低的音板在正中间,音阶向外交替展开,
  排序就是把卡林巴排成另一件乐器。
- `reeds` — 口琴。**气息是乐器的一根轴**,不是格子的属性:十个孔,上排吹下排吸。

`isPlayable` 现在对 26 件全部为真——这是从一开始就该有的断言。

### 三档音色
- **合成**:物理模型。
- **混合**:模型 + 录音的**起音**。听众认出一件乐器基本靠头 0.25 秒(琴槌、拨片、鼓棒),
  而这恰恰是模型最弱、录音最强的地方。所以录音当起音用,然后让位给模型。
- **采样**:FluidR3_GM。**从它发布的地方取,不进仓库**——这是许可证答案不是偷懒:
  CC BY 3.0 的素材放在 MIT 仓库里是个没人想回答的问题,而运行时取 + 在选它的控件上署名
  从构造上回答了它。Service Worker 缓存,第二次访问就离线可用。
- **档位是偏好不是模式**:每档都能演奏每件乐器,没有录音的就回落到模型。
  火车上没信号、或者音源根本不在,代价只是"模型和录音的差别",从来不是一个音。

### 锐评:同一个 bug 在同一份文件里出现了两次
锐评 27 项发现里,**四条 [HIGH] 全是"DOM 对、计数对、几何错"**——
笛子卡片塌成 22px、琴颈自己压自己、舞台从来没被约束过。
最值得记的是:**"手机规则写在基础规则之前,特异性相同时后者胜"这个 bug,
在同一个 style.css 里隔了几周的两个提交各犯了一次**。第二次是我自己犯的。

修完后又发现一批同类的:bar 在手机上 162px(屏幕的 24%,折成 5 行)、
转向后的琴键 1248×34px(330mm 长,真钢琴白键约 150mm)。
两个都违反本项目自己写的规则,而且**都没有任何测试能看见**。

### 用户第二次说"音色不对":逐个量出来的三个 bug
用户说"逐个检查!梳理全部!",于是真的逐个量了 26 件乐器在**真实渲染路径**上的输出。
三个问题,两个是静默的:

1. **八件乐器共用两个音色**——四件 `steel`(吉他/曼陀林/班卓/古筝)、五件 `nylon`
   (尤克里里/琵琶/阮/柳琴/古琴),渲染出的数字**逐字节相同**;整个弓弦家族是
   一个音色弹四个音高。**没有任何东西失败,因为没有东西在检查。**
   数据根本没有描述它命名的乐器。修法是每件乐器一个音色——**琴体就是乐器**:
   班卓是鼓面上的钢弦,古琴是厚桐木上的丝弦,小提琴和大提琴的差别是
   四倍的空气体积、因此低一个半八度的共振峰。
   加的守护断言:**两件乐器不许命名同一个音色**。

2. **激励的亮度和数据是反的**。`dull = dull * brightness + noise * (1 - brightness)`
   是一阶低通,而系数是**平滑量**——所以 `brightness: 0.9` 的钢琴平滑最狠、
   是 app 里最暗的音头(centroid 2357),`brightness: 0.35` 的古琴反而最亮
   (3510)。**每件乐器都在做它数据反面的事。** 修完后古琴 3213、古筝 4060,
   按数据要求的方向排列。

3. **各音色相差 24dB**。根源是**按峰值归一化**:拨弦是"高耸的峰、峰下能量很少",
   持续音正相反;两者归一到同一个峰值,持续音就比拨弦响二十多分贝——
   弹个和弦再吹笛子是一次物理冲击。改成**响度(起音 200ms 的 RMS)为目标、
   峰值只做上限**,24 件建模乐器的差距从 24dB 降到 **4.8dB**。
   注意:标定放在 `audio/render.ts` 而不是模型里,因为它是**回放**的事不是物理的事——
   模型自己的动态(吹得越重越响、低音弦响得久)仍然是模型的事,
   这也是为什么 lib 的测试还能渲染两个气压比较响度。

### 默认档位
用户要求**默认采样、其次混合**:`VOICE_TIERS = ["samples", "hybrid", "synth"]`。
理由站得住:听众认出一件乐器基本靠头 0.25 秒,而三档里只有录音能把它做对;
模型是取不到录音时的回落。

### 用户第三次和第四次报告:两个声音问题 + 一个几何问题
**"合成和混合音色全是噪音"** —— 我的亮度修复**方向对、范围错**。
映射到 `1 - brightness` 把"亮"的激励推到全带宽,那不是拨片,是白噪声爆发;
它**仍然有正确的音高**(所以音高检查看不见),而且**能量集中在头 30ms**
(所以耳朵听见的就是它)。范围收到约 550Hz(拇指)到 6kHz(拨片)。

**"古筝无法下滑"** —— 触摸会把指针**捕获到按下时的那张卡片**,
于是 `pointerenter` 永远不在别的格子上触发,滑音只是"按住不放"。
`PianoKeys` 早就为这个显式释放过捕获,**指板和卡片从来没有**。
而滑音正是指板有、键盘没有的那个手势。

**"弦掉到屏幕外面"** —— 古筝在手机上横向排布时行数是 21,**溢出的是高度**,
而板子被自己的方向而不是"什么真的放不下"告知要横向滚动。
更糟的是它**两次隐身**:`.dashboard` 没有 `min-height: 0` 所以从不收缩、
我新加的 `.shell { overflow: hidden }` 把溢出藏了起来、
而 `assertNoVOverflow` 读的是文档,它报告"没有溢出"而 15 根弦够不到。
新增断言量**舞台到页脚**的距离——"页面不滚动"和"东西在页面上"不是同一句话。

### 用户第五次报告:"采样和混合差别很大" —— 两个系统各有一把尺子
模型的响度是 `render.ts` 标定的,录音的响度是**别人编码时定的**。两个档次放在一起听
就是两个乐器。修法是把**同一把尺子用在录音上**:`loudnessGain()` 用和 `calibrate()`
完全相同的常量、相同的 200ms 窗口去量一段录音,得出它该乘多少。中位差从约 15dB 降到 **0.0dB**,
最坏 4.3dB。

这条必须做对还有一个更硬的理由:**混合档是两者同时响**。起音层低 15dB 的"起音"不是起音,是没人听得见的一层。

**而"量不到"本身也是答案。** FluidR3 的低音提琴 C4 是**三秒静音**——那个音在乐器之外,
从来没被演奏过。把静音放大还是静音,所以 `loudnessGain` 对静音返回 0,由调用方回落到模型。
这是"像低音提琴"和"什么都不像"的差别。

### 银行是有洞的:最近的音 ≠ 最近能用的音
修完静音之后还剩一个更隐蔽的问题:回落到"最近的音",于是低音提琴在低音区是录音、
到中央 C **变回模型**——一件乐器在一个音高上换嗓子,比"多移几个半音"更糟。
`nearestUsable()` 排序后**逐个试到第一个真能发声的**:宁可多移几个半音,
不可在乐器中途换声音。

### 鼓组要自己的录音
GM 的第十信道是**映射不是音色**,预渲染的合集里根本没有打击乐这一档——
所以鼓组不能像别的乐器一样"在同一个银行里填个名字"。@teropa/drumkit 恰好是
九个文件对九件套鼓,这个巧合值得收下。

### 可听性:最锋利的那条断言
逐个审计 26 件乐器时发现**两件检测器完全听不出**:口琴和箫,
比 YIN 能接受的阈值更"喘"(CMND 0.391 / 0.587,阈值 0.34)。
箫的气声就是它的性格,所以把气量收到约十分之一,用更低更暗的管体表达它;
口琴是气流太湍——自由簧需要粗糙的射流,但不能粗糙到簧片不再是信号。
这条现在是对**每一个建模音色**的测试,也是最严的一条:
它是唯一一条会因为"音准对、电平对、频谱对、但仍然不可用"而失败的断言。

### Validation
541 项测试全绿;`vue-tsc --noEmit` 干净;桌面 + 移动双视口 smoke 全绿。
真实 Chrome 实测:13 个模型渲染 0.1–4.9ms 且按音高缓存;
钢琴 C4 过零率 1266→258(高频先死),C2 尾部 RMS 是 C4 的 31 倍(低音弦响得久);
采样档 88 个音 1 秒内解码完成,C4 命中 0 偏移。

### Reusable insight
- **半宽、塌陷、重叠、失控的长度:都是几何问题,而几何问题单测看不见**。
  唯一能发现它们的是让浏览器测量并断言。这一轮里每一条真 bug 都属于这一类。
- **"填满"是几何问题,也是设计问题**。高度给到卡片不等于乐器用上了高度:
  内容居中会让它读成"被拉长的部件"。要找的是**这件乐器在真实世界里怎么占据它那根轴**
  (笛子是管子上的六个孔),然后让内容沿那根轴展开。
- **同一个数值出现在两个地方,就一定会有一天打平**。`z-index: 2` 出现两次,
  谁在上面由 DOM 顺序决定——这种耦合不会报错,只会让一个控件莫名其妙点不动。
- **未测试的那条分支不会自己暴露**。`play()` 和 `hold()` 是同一份 spec 的两个消费者,
  噪声支持只加在了其中一个上,而测试恰好只覆盖了那一个。**消费者多于一个时,
  共通的能力要问两遍。**
- **许可证问题有构造性答案**:不复制进仓库,而是运行时取 + 在使用点署名 + 缓存。
- **物理量写成物理单位可以自解释**:`150mm` 的琴键长度、`23.5mm` 的白键宽、
  `9mm` 的指尖,比任何像素数都多带了"为什么是这个数"。
- **两个来源的东西必须用同一把尺子量**。模型有模型的自律,录音有录音的来路;
  并列之前先把两者归到同一个可测量的量上(RMS),否则"档次"就成了"换了个乐器"。
- **外部的数据是有洞的,而且洞是静默的**。三秒静音和"没这个音"在类型上都是
  `AudioBuffer`,只有量过才知道;查找要问的是"最近的**能用的**",不是"最近的"。
