> **计划外发现并修复的一处真问题**：输入会话上提后,`useTuningLifecycle` 仍在离开 `/tune` 时 `stop()`,
> 与"只选一次"矛盾;但常驻麦克风又是此前锐评抓到的隐私 bug。解法是**引用计数 + 微任务延迟检查**
> (`audio/retention.ts`)——路由切换会先卸载旧视图再挂载新视图,不延迟就会把每次导航都看成"最后一个持有者离开"。

### 起点:两项核心能力被囚禁在 feature 里
`features/tuning/stores/audio-graph.ts` 持有 AnalyserNode（"听进来"归调音）,
`features/metronome/engine/{transport,sound-bank}.ts` 持有调度与发声（"发出去"归节拍器）。
视唱同时需要两者,于是必然撞上"features 互不 import"这条正确的规则。**规则没错,是分层放错了位置。**

### 第一性拆解
这个 app 只有三个原语：**声音流入**（源→帧→特征）、**声音流出**（时间表→发声体）、**乐理意义**（纯数学）。
调音=流入+乐理；节拍器=流出+乐理；时频图=流入+乐理；练耳听辨=流出+乐理；**视唱=三者齐备**。
"一个功能同时用到流入和流出"是常态而非特例 ⇒ 两者都必须是共享层。

### 目标分层
```
lib/       纯：DSP、乐理、频谱缓冲、配色、刻度、i18n、persist。禁令：不得出现 Web Audio / DOM 全局
audio/     唯一接触 Web Audio 的层
           context.ts 租约 | source.ts 应用级输入会话 | capture.ts 可多路 analyser tap
           analysis.ts 帧→特征流 | transport.ts 调度 | voice.ts 发声体
features/* 组合与呈现,互不相引
router/    唯一能点名 feature 视图的地方
```
依赖严格单向 `features → audio → lib`。边界测试（已是解析 import 图）需补两条：
`lib/` 不得引 `audio/`；**只有 `audio/` 可引用 Web Audio 全局**（`new AudioContext` 全仓库仅一处）。

### 五个建模决策
1. **唯一时间基 = `context.currentTime`**。分析循环把 rAF 的 `performance.now()` 换成音频时间。
   `AnalysisPipeline` 本就是"帧+时钟"形状,换注入值即可,测试不动。收益：频谱列、音高轨迹、节拍点、
   答题时刻落在同一条时间线上 —— **视唱评分不再需要任何对齐代码**。
2. **输入是应用级会话**。`audio/source.ts` 持有当前源；`SourceBar` 升为共享组件,由需要它的工具各自摆放
   （仍不进 shell）。用户直觉是"选一次麦克风,整个 app 在听"。
3. **分析是实例不是单例**。`createCapture({fftSize, smoothing})` 返回可订阅句柄 + `dispose()`。
   删除 `analysis-loop.ts` 的模块级可变状态与全局 `spectrumTargets: Set`。
   顺带解开 `stability` 的双重语义（现在同时驱动 analyser 平滑与 pipeline 稳定判据 —— 两个旋钮各自命名）。
4. **视图 = 一条流 × 一组刻度 的投影**。`lib/plot/scale.ts` 提供 `logFreq/semitone/time/db → 0..1`,
   是刻度的唯一真相；`frequencyToX` 的轴向耦合消失。半音刻度使"跑高半音=固定垂直距离",视唱最需要。
   `draw.ts` 内嵌的两份调色板改为从 `tokens.css` 读一次注入。
5. **凡可枚举皆数据**：发声体 = {波形,包络,泛音}；练耳题型 = `generator(rng) → Exercise` + 判分容差；
   配色 = 查找表。硬判据：*加一个题型/音色/配色,能否只加数据、不碰引擎与 UI？*

### 时频图（/scope）的技术要点
- **不能复用调音的 analyser**：FFT 16384 @48k 时间窗 ≈341 ms + smoothing 0.8,瀑布图会在时间轴糊掉。
  从同一 source 并联第二路 tap：**fftSize 2048、smoothing 0**。向用户暴露为"时间清晰 ↔ 频率清晰"滑块,不暴露 fftSize 数字。
- **不用自滚动画布**（`drawImage` 左移一像素）：那会把时间轴绑死在帧率上,暂停/缩放/导出都做不了。
  改为**环形缓冲 + 每帧重绘**：`Column {t, db: Float32Array(256 bands), pitchHz}`,采集固定 20–30 Hz 与 rAF 解耦,
  `window(endTime, seconds)` 取视图。60 s×30 Hz×256×4B ≈1.8 MB。每帧 `putImageData` 一次,不逐条 `fillRect`。
  **冻结/回看天然可行**（唱完一句回看音准）。
- **colormap 必须配 dB 范围控制**（floor/ceiling 默认 -90/-20 + 自动增益）,否则换配色无意义；右侧画带刻度的 colorbar。
  默认深色 `magma`,浅色主题换 `ice`/反转灰度。
- **参考音**统一为 `{hz, label, kind: "target"|"manual"|"detected"}`：跟随当前 `TuningTarget` / 手动选音 / 谐波辅助线（2×3×4×,虚线）。
  再叠检测音高轨迹 —— 视唱评分的可视化部分在此免费获得。
- y 轴提供对数 Hz 与**半音刻度**两种。

### 音高曲线图层（参考实物 app：知唱音域音调仪）
它**不是第三个视图,是决策④的推论**：与时频图共用同一环形缓冲、同一时间轴、同一 `semitone()` 刻度,
只是取 `Column.pitchHz` 而非 `Column.db`,渲染为折线而非色块 ⇒ `/scope` 画布上的一个**可开关图层**。
默认：乐器场景开时频图层,人声/视唱场景默认只开音高曲线层（更干净）。y 轴音名标签左右两侧各一列。
四个独有决定：
1. **分段绘制,绝不插值跨越**：`pitchHz` 为 null 或低于静音门限就断开。否则换气会渲染成假滑音
   （参考图里音符尾部那些垂直陡降就是这个缺陷）。
2. **录制回放 + 固定游标**：实时用右缘增长；一条 take 提交后（拷出窗口内的列 + 时长）改为固定游标回放,
   底部走 `mm:ss.xx / 总时长`。唱完回看比唱时看有用得多。
3. **音域统计**：take 结束后对缓冲做纯函数统计,去掉起音滑音与八度跳变后取百分位 ⇒ "你的音域 F2–C5"。零成本高价值。
4. **八度错误是曲线视图独有的风险**：人声在气声/低音区易半频倍频跳变,画成曲线会看到整齐的八度阶跃。
   轨迹层需一层**连续性约束**（相邻列跳变 >~7 半音时优先判为八度误判而非真跳跃）,时频图不需要这层。

视唱评分时把**目标旋律画成背景水平线段**,用户轨迹叠在其上 —— 共用时间轴与半音刻度,对错肉眼可见,
不需要任何对齐代码。这是"统一时间基"那笔投资的兑现处。

### 练耳（/ear）
- 内部沿用节拍器已被验证的分层：`domain/`（出题、判分、难度阶梯,纯函数）→ `engine/`（player 依赖共享 Transport+voice；
  sing-judge 消费 AnalysisPipeline,注入时钟）→ `stores/` → UI。
- **出题必须注入随机源** `rng: () => number`,否则无法单测；顺带获得可分享的每日 seed。
- 内容梯队（按 复用度÷成本 排序）：① 音程/和弦性质/音阶/单音辨识（纯听+点选,只依赖 voice；和弦复用 `CHORD_TYPES`）
  ② 旋律听写/节奏听写/和声进行（复用 `key.ts` 的 `degreeOf` 出级数）③ 视唱评分、音高保持 ④ 每日任务、错题重练。
- 判分 `Verdict {correct, centsOff?, msOff?}`：音准取**稳定段中位音分**（先过 pipeline 的静音与稳定判据,避免起音滑音被判跑调）,
  容差 ±25/±50；节奏容差按 BPM 缩放（±15% 拍长）。**答题时间戳取自 `context.currentTime`,不用 UI 时间戳。**
- 进度经 `lib/persist.ts`（`ml.ear.*`）,按最近 N 次正确率自适应升降级（>85% 升,<60% 降）。
- 记谱**自绘 SVG**（布局是纯函数,可单测）+ 简谱模式；不引 VexFlow/abcjs（与全客户端轻依赖 PWA 定位冲突）。
  第一、二梯队用唱名/字母即可,先不画谱。

### 用户直觉:路由按意图动词切
`/tune`（把这个音调准）| `/scope`（看见这个声音）| `/rhythm`（跟着拍子）| `/ear`（练耳朵和嗓子）。
**把时频图从调音页拆出是唯一需要判断的一刀**：调音的意图是"对准一个数",视线焦点在指针；时频图是"探索一段声音",
需要大画布与回看。两种意图共处一页会争夺屏幕 —— 与"布局服从用途"同一条理由。建议拆。
工具专属设置继续走 `ControlSheet`（点你要改的那个值来改它）,不新增面板。

### 验收标准
- 加乐器/音色/题型/配色,都只改数据文件
- 删掉任一 feature,其余功能照常工作
- `lib/` 无一行 Web Audio；`new AudioContext` 全仓库仅一处

- 用户全程只选一次输入源

### Reusable insight
- **"两个 feature 需要同一件东西"不是要放宽边界规则,而是这件东西的层放低了。** 边界规则正确时,它给出的编译错误就是分层信号。
- **原则不变、结论可变**：把规则写成"谁用谁拥有",使用者数量变化时结论自动更新；写成"放在 tuning 里"就会过期。
- **统一时间基是一次性投资、永久红利**：能叠图的前提是同一条时间线,否则每个新功能都要写一遍对齐代码。
- **兼容代码要写落日日期**,否则包袱只增不减。
